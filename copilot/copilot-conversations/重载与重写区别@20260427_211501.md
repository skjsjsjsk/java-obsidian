可以改成下面这种更标准的版本：

---

- 重载（Overload）：
	- 发生在**同一个类中**，方法名相同，但**参数列表不同**（参数个数、类型、顺序不同）。
	- 与**返回值无关**，仅仅返回值不同不构成重载。
	- 构造方法也可以构成重载，比如无参构造和有参构造。

- 重写（Override）：
	- 发生在**父子类之间**，子类对父类的方法进行重新实现。
	- 方法名、参数列表必须相同。
	- 返回值类型要相同，或者是其子类（协变返回类型）。
	- 子类方法的访问权限**不能比父类更严格**。
	- 子类重写方法**不能抛出比父类更大的检查异常**。
	- `static`、`final`、`private` 方法不能被重写。
	- `static` 方法只能被隐藏，不能被重写。

---

你原来“重写其他所有的都相同，但是方法体不同”这句话，问题在于：

- “其他所有的都相同”不严谨  
  因为返回值可以是父类返回值的子类型，不一定完全相同。
- 访问修饰符也不一定完全相同  
  例如父类是 `protected`，子类可以重写成 `public`。
- 异常声明也有规则，不是“所有都相同”。

---

你可以直接在笔记里写成适合面试背诵的版本：

- 重载就是一个类中多个同名方法的**参数列表不同**，和返回值无关。
- 重写就是子类对父类方法的重新实现，要求**方法名和参数列表相同**，返回值要兼容，访问权限不能缩小，抛出的检查异常不能扩大。

**ai**: 可以这样理解：

- is-a：**是一个**
- has-a：**有一个**

它们描述的是类和类之间不同的关系。

---

### 1. is-a
表示**继承关系**，也就是“子类是父类的一种”。

比如：

- Dog is a Animal
- Cat is a Animal

Java 里一般体现为：

```java
class Animal {
}

class Dog extends Animal {
}
```

这里 `Dog` 是 `Animal` 的一种，所以这是 **is-a** 关系。

面试里可以说：

- is-a 表示继承关系
- 子类属于父类的一种更具体的类型
- 满足里氏替换原则时，父类出现的地方可以用子类替代

---

### 2. has-a
表示**组合 / 聚合关系**，也就是“一个类拥有另一个类作为成员”。

比如：

- Car has a Engine
- Person has a Address

Java 里一般体现为成员变量：

```java
class Engine {
}

class Car {
    private Engine engine;
}
```

这里 `Car` 里有一个 `Engine` 对象，所以这是 **has-a** 关系。

面试里可以说：

- has-a 表示一个类包含另一个类
- 一般通过成员变量来体现
- 属于组合或聚合思想，比继承更灵活

---

### 3. 两者区别
| 区别 | is-a | has-a |
| --- | --- | --- |
| 含义 | 是一个 | 有一个 |
| 关系 | 继承 | 组合/聚合 |
| 实现方式 | `extends` / `implements` | 成员变量 |
| 耦合性 | 更强 | 更灵活 |

---

### 4. 你笔记里那句有点问题
你之前写的是：

- 抽象类是 is-a 的关系
- 接口是 has-a 的关系

这句话**不准确**。

更准确地说：

- 类继承抽象类，通常体现的是 **is-a**
- 类实现接口，更多表示“具备某种能力”，本质上也更接近一种 **行为规范**
- has-a 一般不是指接口，而是指“成员包含关系”

比如：

```java
class Bird extends Animal implements Flyable {
}
```

这里：

- `Bird extends Animal` 是 **is-a**
- `Bird implements Flyable` 表示 `Bird` 具有飞行能力
- 如果 `Bird` 里有一个 `Wing` 成员变量，那才是 **has-a**

---

### 5. 面试简洁回答版
你可以直接背这个：

- is-a 表示继承关系，意思是“子类是父类的一种”，比如 `Dog is a Animal`。
- has-a 表示包含关系，意思是“一个类拥有另一个类作为成员”，比如 `Car has a Engine`。
- 一般来说，继承体现 is-a，成员组合体现 has-a。

---

- 抽象类和接口：
	- 抽象类和接口都不能被实例化，都可以用于定义规范，让子类去实现具体逻辑。
	- 抽象类更适合描述一类对象的**共性**，体现的是 **is-a** 关系；接口更适合描述一种**能力或行为规范**。
	- 一个类只能继承一个抽象类，但可以实现多个接口。

- 抽象类的特点：
	- 可以包含抽象方法，也可以包含普通方法。
	- 可以有成员变量、构造方法和代码块。
	- 子类通过 `extends` 继承抽象类。
	- 更适合为一组相关类提供公共属性和通用方法，便于代码复用。

- 接口的特点：
	- 接口中的方法本质上是对行为的约束，类通过 `implements` 来实现接口。
	- 一个类可以实现多个接口，因此接口比抽象类更灵活。
	- 接口更强调“能做什么”，比如 `Runnable` 表示可以被线程执行，`Comparable` 表示对象之间可以比较。
	- 在 Java 8 之后，接口中可以有 `default` 默认方法和 `static` 静态方法；Java 9 之后还可以有私有方法。

- 两者的区别：
	- 抽象类体现的是继承关系，通常是 **is-a**，比如 `Dog` 是一种 `Animal`。
	- 接口更偏向于行为规范，不属于 **has-a**；**has-a** 一般表示包含关系，也就是一个类中持有另一个类的对象作为成员变量。
	- 抽象类可以有状态和部分实现，接口更适合定义规范和扩展能力。
	- 抽象类适合“多个子类有共同属性和方法”的场景，接口适合“多个类都具备某种能力”的场景。

- 为什么类不能多继承：
	- 因为如果一个类同时继承多个父类，而多个父类中有同名同参数的方法，子类在调用时就会产生二义性，不知道该继承哪一个实现。
	- 这就是多继承带来的菱形继承问题，所以 Java 中类不支持多继承。

- 为什么接口可以多实现：
	- 因为接口主要定义的是方法规范，早期接口中没有方法实现，不会产生实现冲突。
	- 即使 Java 8 之后接口支持默认方法，如果多个接口中存在同名默认方法，Java 也要求实现类必须显式重写来解决冲突。

- 抽象类体现 is-a 关系，一个类只能继承一个抽象类；接口体现行为扩展，一个类可以实现多个接口。
- 抽象类可以有成员变量、构造方法和普通方法，接口更轻量、更灵活，适合解耦和扩展。
