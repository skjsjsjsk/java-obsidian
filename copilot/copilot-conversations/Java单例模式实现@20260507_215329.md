## 1. 饿汉式

```java
public class Singleton {

    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {
    }

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

- 优点:
	- 实现简单
	- 线程安全，因为类加载过程由 JVM 保证线程安全
- 缺点:
	- 类一加载就创建对象，如果一直不用，会浪费资源

面试说法：

> 饿汉式是在类加载时就创建单例对象，利用 JVM 类加载机制保证线程安全，但是缺点是不能懒加载。

---

## 2. 懒汉式，线程不安全

```java
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

- 优点:
	- 支持懒加载
- 缺点:
	- 线程不安全

问题场景：

```java
if (instance == null) {
    instance = new Singleton();
}
```

如果多个线程同时判断 `instance == null`，可能会创建多个对象。

面试中一般不推荐这种写法。

---

## 3. 懒汉式，加 synchronized

```java
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

- 优点:
	- 线程安全
	- 支持懒加载
- 缺点:
	- 每次调用 `getInstance()` 都要加锁，性能较差

面试说法：

> 这种方式虽然解决了线程安全问题，但是锁的粒度太大，每次获取实例都要竞争锁，性能不太好。

---

## 4. 双重检查锁 DCL，常考

```java
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 为什么要判断两次？

第一次判断：

```java
if (instance == null)
```

是为了避免实例已经创建后，后续线程每次都进入 synchronized，提高性能。

第二次判断：

```java
if (instance == null)
```

是为了防止多个线程同时通过第一次判断后，排队进入 synchronized，导致重复创建对象。

### 为什么 instance 要加 volatile？

因为这行代码：

```java
instance = new Singleton();
```

并不是原子操作，大概可以分为三步：

```java
1. 分配对象内存空间
2. 初始化对象
3. 将 instance 指向这块内存空间
```

如果没有 `volatile`，可能发生指令重排，变成：

```java
1. 分配对象内存空间
2. 将 instance 指向这块内存空间
3. 初始化对象
```

这样线程 A 还没初始化完对象，线程 B 判断 `instance != null`，直接返回了一个未初始化完成的对象，可能导致异常。

所以 `volatile` 的作用是：

- 保证可见性
- 禁止指令重排

面试说法：

> DCL 通过两次 null 判断减少锁竞争，通过 synchronized 保证创建过程的线程安全，通过 volatile 禁止指令重排，防止其他线程拿到半初始化对象。

## 5. 静态内部类，推荐

```java
public class Singleton {

    private Singleton() {
    }

    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}
```

- 优点:
	- 线程安全
	- 支持懒加载
	- 实现简单
	- 性能好

原理：

- 外部类 `Singleton` 加载时，不会立即加载内部类 `SingletonHolder`
- 只有调用 `getInstance()` 时，才会加载 `SingletonHolder`
- JVM 会保证类加载过程的线程安全，所以 `INSTANCE` 只会被创建一次

面试说法：

> 静态内部类是比较推荐的单例实现方式。它利用 JVM 类加载机制保证线程安全，同时内部类只有在调用 getInstance 方法时才会被加载，所以也实现了懒加载。

## 6. 枚举单例，最安全

```java
public enum Singleton {
    INSTANCE;

    public void doSomething() {
        System.out.println("do something");
    }
}
```

使用：

```java
Singleton.INSTANCE.doSomething();
```

- 优点:
	- 写法最简单
	- 天然线程安全
	- 防止反射破坏单例
	- 防止反序列化破坏单例

面试说法：

> 枚举单例是《Effective Java》推荐的实现方式。它不仅线程安全，而且可以天然防止反射和反序列化破坏单例，是最安全的单例实现方式。

---

## 面试重点：反射和反序列化会破坏单例吗？

普通单例可能被反射破坏：

```java
Constructor<Singleton> constructor = Singleton.class.getDeclaredConstructor();
constructor.setAccessible(true);
Singleton s1 = constructor.newInstance();
Singleton s2 = constructor.newInstance();
```

这样可能创建多个对象。

普通单例也可能被反序列化破坏，因为反序列化会重新创建对象。

解决反序列化破坏单例，可以加：

```java
private Object readResolve() {
    return getInstance();
}
```

但是枚举单例天然可以防止反射和反序列化破坏。

## 面试推荐回答

如果面试官问：单例模式怎么实现？

可以这样回答：

> 单例模式的核心是保证一个类只有一个实例，并提供全局访问点。常见实现方式有饿汉式、懒汉式、双重检查锁、静态内部类和枚举单例。  
> 饿汉式线程安全，但是不支持懒加载；普通懒汉式支持懒加载，但是线程不安全；加 synchronized 可以保证线程安全，但是性能较差。  
> 实际比较常用的是双重检查锁和静态内部类。DCL 需要用 volatile 修饰实例变量，防止 new 对象过程发生指令重排，导致其他线程拿到半初始化对象。  
> 静态内部类利用 JVM 类加载机制保证线程安全，同时也支持懒加载，是比较推荐的写法。  
> 如果追求最安全的实现，可以使用枚举单例，因为它天然线程安全，并且可以防止反射和反序列化破坏单例。
