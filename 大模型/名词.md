# Function Calling, MCP和Skill
- Function Calling: 
	- 就是大模型用来和外部工具交互的, 开发者自己定义好tool的名称了, 用途了, 参数了, 然后调用时按照约定输出, 通常是JSON格式. 
- MCP: 
	- MCP就是Agent中的 `USB-C` 接口
	- 因为Funciton Calling 对于不同的厂家来说有不同的规范, 导致同一个工具对于不同的大模型都要重写一遍. 为了解决这个, 就出现了MCP, 它是一个标准化的接入协议, 按照MCP的规范去写工具, 服务方实现一次MCP Server，应用方接入MCP Client，即插即用。
	- 流程使用MCP的: 
		- 用户请求 -> MCP Client 收到请求, 按照MCP格式把 `问题和工具列表` 打包给大模型 -> 大模型决定调用哪个工具, 生成指令(按照MCP规范) -> MCP Client 解析指令, 调用MCP Server的工具 -> 执行结果按MCP格式返回给大模型
- Skill: 
	- 其实就是对于某个能力或者是任务流程的封装. 它不仅仅是个工具, 而是把prompt, 调用规则, 输入输出约束, 任务流程封装起来成为一个可复用的模块
	- 渐进式披露: 
		- 总的来说就是Agent启动时只会看所有skill的名字, 需要时加载详细内容
		- 如何做呢? 有个三层加载架构: 
			- 第一层: Agent启动时候, 就是你有的所有的skill的 `Frontmatter` , 即`name`和`description`加载到agent自己的 `system prompt` 里面
			- 第二层: 发现任务于某个skill相关了, 那么就去读取该skill完整的SKILL.md的内容, 把详细的工作流程加载到上下文中
			- 第三层: 就是对应的剩余的脚本, 模板还有参考的文档了等等. 这些资源不会直接加载进去, 而是当需要的时候再读取, 这就使得这些附属的资源可以很大, 因为它们不会在Agent启动时占据上下文, 可以在运行时访问
# agnet memory如何设计:
- 分为短期记忆和长期记忆:
	- 短期记忆就是当前的对话上下文, 上下文窗口有限, 不可能把所有的历史记录全部传入
		- 所以一般使用**滑动窗口**, 就是只使用最近5轮的对话传入prompt中, 超出这个轮次的对话直接截断; 
		- 或者对**对话进行总结**, 包含大概的摘要, 关键信息等等, 把摘要和最近5轮的对话一同传给prompt, 但是这样会丢失细节;
		- **选择性的保留关键信息**: 不保存全部的对话, 而是提取出对话中的关键信息, 比如用户的明确指令了, 工具调用的结果了之类的, 丢弃不重要的信息, 比如闲聊的内容了之类的, 可以通过设定规则来判断哪些信息重要
		- 对于多agent多步任务来说, 可以维护一个scratchpad(工作区), 就是把任务的关键的状态, 比如已经完成了的步骤, 当前处理的中间结果, 未完成的步骤这些存储起来放到一块, 每轮调用都带上, 方便LLM寻找
	- 长期记忆: 就是把记忆持久化到外部存储, 比如使用向量数据库了等等, 因为长期记忆是要跨会话的, 当然写入也不能全部写入, 要有自己的写入机制
		- 比如可以把历史对话的摘要了, 用户的偏好了, 执行的经验了等等存储到向量数据库中, 需要的时候去检索. 同时对于存储好的记忆, 要能够被淘汰或者更新, 比如使用时间衰减了, 给予一个权重, 调用就增加, 不用就减少, 低于一定值就删除
# 既然上面提到了长期记忆存储要要有**遗忘机制, 写入机制**等等, 那该如何设计呢?
- 对于写入机制: (为啥不全部保存呢, 会增加噪声; 提炼不好呢, 那就检索精度下降了)
	- 可以在会话结束的时候**使用LLM进行提炼**, 抽取出用户偏好了, 关键的事实了之类的, 过滤掉闲聊这种无意义的内容, 输出一个JSON格式, 再去保存.  同时
	- 对于用户明确说的像 "记住我现在的项目用的JDK21" 等等这样的话, 那么就要**在对话过程中进行实时写入**, 而非等到结束. 
		- 可以用规则检测显示记忆的出现, 然后做即使写入
	- 同时对于**记忆存储要进行分类**, 方便检索. 
		- 比如**做用户画像**, 记住用户的偏好了, 背景了这种, 一般不会变, 在每次用户开启对话时直接加载进去; 
		- 还有就是**对于事实类的**, 像用户的项目信息, 技术栈这种, 可能会变化, 做好版本管理; 
		- 还有就是**交互经验类**, 比如那种策略在哪种环境下更好, 便于下次碰到同样的情况能够更好的处理, 优化Agent的行为; 
		- 还有像**任务上下文**, 比如上一次任务的进度等等, 便于下次对话的延续. 
- 对于遗忘机制: 
	- 首先就是时间衰减, 保存记忆时有创建的时间, 检索的时候时间越久权重越低, 降低其优先级
	- 其次保存记忆时发现是相同的信息, 那么可以进行显示的覆盖, 不同新增, 淘汰可以用LRU策略, 根据访问的频率进行淘汰, 低于一定值就删除
