**问题 1：Agent 基础设计**

假设你要做一个“个人知识库 Agent”，用户可以上传 PDF、Markdown、网页链接，然后用自然语言提问。Agent 需要：

- 能基于用户资料回答问题
- 能在资料不足时说明不知道
- 能调用一个搜索工具补充外部信息
- 能给出引用来源
- 支持多轮对话

请你从高层架构讲起：这个系统会包含哪些核心模块？一次用户提问从进入系统到返回答案，大致会经过哪些步骤？

**问题 2：RAG 质量问题排查**

你上线了这个个人知识库 Agent。用户反馈：  
“我明明上传了相关 PDF，但 Agent 经常答非所问，或者说找不到资料。”

你会如何排查这个问题？请从 **文档处理、索引、检索、重排、Prompt、模型生成** 这几个环节讲。

**问题 3：Agent 工具调用设计**

现在这个知识库 Agent 增加三个工具：

- search_web(query)：联网搜索
- read_document(doc_id, page)：读取指定文档页
- create_note(title, content)：把回答整理成笔记保存

请你设计一个 Agent 调用工具的流程。重点回答：

1. 模型如何知道有哪些工具、每个工具怎么用？
2. 工具调用参数怎么校验？
3. 怎么避免模型乱调用工具或重复调用工具？
4. 工具执行失败时怎么处理？

**问题 4：Agent 记忆设计**

你要给这个 Agent 加“长期记忆”功能。比如用户说：

> “以后回答我都尽量用 Python 举例。”  
> “我的项目主要使用 FastAPI、PostgreSQL 和 LangChain。”  
> “不要记录这句话。”

请你设计长期记忆模块。请回答：

1. 哪些内容应该写入长期记忆？哪些不应该？
2. 如何从对话中提取记忆？
3. 记忆如何存储和检索？
4. 用户如何查看、修改或删除记忆？
5. 如何避免记忆污染后续回答？

**问题 5：后端接口与任务流程设计**

现在你要把这个 AI/Agent 系统做成后端服务，提供给前端或其他客户端调用。它需要支持：

- 上传文档
- 查询文档处理状态
- 发起对话
- 流式返回模型回答
- 查看会话历史
- 管理长期记忆

请你设计一组后端 API。你可以用 REST 或 WebSocket / SSE。请说明：

1. 你会设计哪些核心接口？
2. 哪些操作应该异步处理？
3. 流式回答怎么实现？
4. 如何区分用户、会话、文档和消息？

**问题 6：AI 应用评测与监控**

你的 Agent 上线后，老板问你：“我们怎么知道它真的变好了？不能每次改 Prompt、换模型、调 chunk size 都靠人工感觉。”

请你设计一套评测与监控方案。请回答：

1. 离线评测怎么做？
2. 线上监控哪些指标？
3. 如何评估 RAG 的检索质量和最终回答质量？
4. 如果发现幻觉率升高，你会怎么定位问题？
