## 需要修正的点

### 1. “载入”建议改成“加载”

面试里更标准的说法是：

- 加载
- 连接
- 初始化

连接又包括：

- 验证
- 准备
- 解析

所以可以把“载入”改成“加载”，更符合 JVM 术语。

---

### 2. 准备阶段对 `static final` 的描述需要更严谨

你写的是：

> 如果是 static final 修饰的静态变量，会直接赋值代码中指定的值

这个说法**不完全准确**。

更严谨地说：

- 准备阶段会给**类变量**，也就是 `static` 变量分配内存，并设置**零值**
- 如果是被 `static final` 修饰，并且是**编译期常量**，准备阶段会直接赋代码中的值
- 如果不是编译期常量，即使是 `static final`，也要等到初始化阶段才真正赋值

例如：

```java
public class Test {
    static int a = 10;
    static final int b = 20;
    static final Integer c = 30;
    static final int d = new Random().nextInt();
}
```

准备阶段大致是：

```java
a = 0;
b = 20;
c = null;
d = 0;
```

原因是：

- `static int a = 10`：普通静态变量，准备阶段先是默认值 `0`，初始化阶段才赋值为 `10`
- `static final int b = 20`：编译期常量，准备阶段直接赋值为 `20`
- `static final Integer c = 30`：不是基本类型常量，本质涉及装箱和对象引用，准备阶段是 `null`
- `static final int d = new Random().nextInt()`：运行期才能确定，准备阶段是 `0`

所以你文档里这句话建议改成：

> 准备阶段会为类变量，也就是静态变量分配内存，并设置默认零值。对于 `static final` 修饰的编译期常量，会在准备阶段直接赋值为代码中指定的常量值；其他静态变量要等到初始化阶段才赋真实值。

---

### 3. 初始化阶段的描述可以补充 `<clinit>()`

你写的：

> 初始化阶段会执行静态代码块和静态变量的初始化，就是把代码里面的值赋值给静态变量

这个是对的，但面试里可以更标准：

> 初始化阶段会执行类构造器 `<clinit>()` 方法，`<clinit>()` 是由编译器自动收集类中的静态变量赋值语句和静态代码块合并生成的，执行顺序与代码中的出现顺序一致。

例如：

```java
public class Test {
    static int a = 1;

    static {
        a = 2;
    }

    static int b = 3;
}
```

初始化阶段会按照源码顺序执行：

```java
a = 1;
a = 2;
b = 3;
```

---

### 4. “解析”阶段不一定严格发生在初始化之前

你现在写：

> 连接分为验证、准备和解析

这没问题。

但是如果面试官追问，最好知道：

- 验证、准备、解析属于连接阶段
- 但 JVM 规范允许解析阶段在初始化之后再进行
- 也就是说，解析可能是懒加载式的，不一定一次性全部完成

普通面试不一定需要主动说，但知道更好。

```markdown
- 类加载机制:
	- 了解类加载机制吗: 了解。JVM 会把类的二进制字节流加载到内存中，并对数据进行验证、准备、解析和初始化，最终形成 JVM 可以直接使用的 Class 对象，这个过程就叫做类加载机制。
	- 讲一下类加载的过程: 类加载过程主要分为三个阶段，分别是加载、连接和初始化。
		- 加载: 通过类的全限定名获取该类的二进制字节流，将字节流代表的静态存储结构转化为方法区的运行时数据结构，并在堆中生成一个代表该类的 `java.lang.Class` 对象，作为访问方法区中类数据的入口。
		- 连接: 连接又分为验证、准备和解析三个阶段。
			- 验证: 检查 Class 文件的字节流是否符合 JVM 规范，保证不会危害虚拟机安全。

			- 解析: 将常量池中的符号引用替换为直接引用。
		- 初始化: 初始化阶段会执行类构造器 `<clinit>()` 方法。`<clinit>()` 方法是由编译器自动收集类中的静态变量赋值语句和静态代码块合并生成的，执行顺序与代码中的出现顺序一致。
```
