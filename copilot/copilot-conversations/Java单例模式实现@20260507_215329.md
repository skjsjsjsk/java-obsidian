## 1. 饿汉式

```java
public class Singleton {

    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {
    }

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

- 优点:
	- 实现简单
	- 线程安全，因为类加载过程由 JVM 保证线程安全
- 缺点:
	- 类一加载就创建对象，如果一直不用，会浪费资源

面试说法：

> 饿汉式是在类加载时就创建单例对象，利用 JVM 类加载机制保证线程安全，但是缺点是不能懒加载。

---

## 2. 懒汉式，线程不安全

```java
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

- 优点:
	- 支持懒加载
- 缺点:
	- 线程不安全

问题场景：

```java
if (instance == null) {
    instance = new Singleton();
}
```

如果多个线程同时判断 `instance == null`，可能会创建多个对象。

面试中一般不推荐这种写法。

---

## 3. 懒汉式，加 synchronized

```java
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

- 优点:
	- 线程安全
	- 支持懒加载
- 缺点:
	- 每次调用 `getInstance()` 都要加锁，性能较差

面试说法：

> 这种方式虽然解决了线程安全问题，但是锁的粒度太大，每次获取实例都要竞争锁，性能不太好。

## 4. 双重检查锁 DCL，常考

```java
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 为什么要判断两次？

第一次判断：

```java
if (instance == null)
```

是为了避免实例已经创建后，后续线程每次都进入 synchronized，提高性能。

第二次判断：

```java
if (instance == null)
```

是为了防止多个线程同时通过第一次判断后，排队进入 synchronized，导致重复创建对象。

### 为什么 instance 要加 volatile？

因为这行代码：

```java
instance = new Singleton();
```

并不是原子操作，大概可以分为三步：

```java
1. 分配对象内存空间
2. 初始化对象
3. 将 instance 指向这块内存空间
```

如果没有 `volatile`，可能发生指令重排，变成：

```java
1. 分配对象内存空间
2. 将 instance 指向这块内存空间
3. 初始化对象
```

这样线程 A 还没初始化完对象，线程 B 判断 `instance != null`，直接返回了一个未初始化完成的对象，可能导致异常。

所以 `volatile` 的作用是：

- 保证可见性
- 禁止指令重排

面试说法：

> DCL 通过两次 null 判断减少锁竞争，通过 synchronized 保证创建过程的线程安全，通过 volatile 禁止指令重排，防止其他线程拿到半初始化对象。

## 5. 静态内部类，推荐

```java
public class Singleton {

    private Singleton() {
    }

    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}
```

- 优点:
	- 线程安全
	- 支持懒加载
	- 实现简单
	- 性能好

原理：

- 外部类 `Singleton` 加载时，不会立即加载内部类 `SingletonHolder`
- 只有调用 `getInstance()` 时，才会加载 `SingletonHolder`
- JVM 会保证类加载过程的线程安全，所以 `INSTANCE` 只会被创建一次

面试说法：

> 静态内部类是比较推荐的单例实现方式。它利用 JVM 类加载机制保证线程安全，同时内部类只有在调用 getInstance 方法时才会被加载，所以也实现了懒加载。

## 6. 枚举单例，最安全

```java
public enum Singleton {
    INSTANCE;

    public void doSomething() {
        System.out.println("do something");
    }
}
```

使用：

```java
Singleton.INSTANCE.doSomething();
```

- 优点:
	- 写法最简单
	- 天然线程安全
	- 防止反射破坏单例
	- 防止反序列化破坏单例

面试说法：

> 枚举单例是《Effective Java》推荐的实现方式。它不仅线程安全，而且可以天然防止反射和反序列化破坏单例，是最安全的单例实现方式。

## 面试重点：反射和反序列化会破坏单例吗？

普通单例可能被反射破坏：

```java
Constructor<Singleton> constructor = Singleton.class.getDeclaredConstructor();
constructor.setAccessible(true);
Singleton s1 = constructor.newInstance();
Singleton s2 = constructor.newInstance();
```

这样可能创建多个对象。

普通单例也可能被反序列化破坏，因为反序列化会重新创建对象。

解决反序列化破坏单例，可以加：

```java
private Object readResolve() {
    return getInstance();
}
```

但是枚举单例天然可以防止反射和反序列化破坏。

> 判断 `instance == null` 和创建对象 `new Singleton()` 这两个操作不是一个原子操作，多个线程可能同时进入判断，从而创建多个对象。

## 先看普通懒汉式代码

```java
public class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

正常单线程情况下没问题：

```java
Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();
```

第一次调用时：

```java
instance == null
```

所以创建对象：

```java
instance = new Singleton();
```

第二次调用时：

```java
instance != null
```

直接返回之前的对象。

---

## 多线程下为什么出问题？

假设现在有两个线程：

- 线程 A
- 线程 B

它们几乎同时调用：

```java
Singleton.getInstance();
```

执行过程可能是这样：

| 时间 | 线程 A | 线程 B |
|---|---|---|
| 1 | 判断 `instance == null`，结果为 true | |
| 2 | | 判断 `instance == null`，结果也为 true |
| 3 | 执行 `new Singleton()`，创建对象 A | |
| 4 | | 执行 `new Singleton()`，创建对象 B |
| 5 | 把对象 A 赋值给 `instance` | |
| 6 | | 把对象 B 赋值给 `instance` |

结果就是：

- 线程 A 创建了一个对象
- 线程 B 也创建了一个对象

这就违反了单例模式“只创建一个对象”的要求。

---

## 问题代码就在这里

```java
if (instance == null) {
    instance = new Singleton();
}
```

这段代码不是线程安全的。

它至少包含两个关键动作：

```java
1. 判断 instance 是否为空
2. 如果为空，创建对象并赋值
```

多个线程可能同时完成第 1 步判断，然后都进入创建对象的逻辑。

---

## 用一句生活例子理解

假设办公室只有一个打印机，规则是：

```java
if (办公室没有打印机) {
    买一台打印机;
}
```

如果两个人同时检查：

- A 看了一眼：没有打印机
- B 也看了一眼：没有打印机

然后：

- A 去买了一台
- B 也去买了一台

最后办公室就有两台打印机了。

这就是懒汉式线程不安全的原因。

## 怎么解决？

可以给方法加锁：

```java
public static synchronized Singleton getInstance() {
    if (instance == null) {
        instance = new Singleton();
    }
    return instance;
}
```

这样同一时刻只有一个线程能进入 `getInstance()` 方法，就不会重复创建对象。

不过这种方式性能一般，因为每次调用都要加锁。

更推荐的是双重检查锁：

```java
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```
