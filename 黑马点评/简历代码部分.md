# 项目关键代码梳理

本文档整理了从“秒杀链路优化”开始，到后续“缓存优化”“数据一致性保证”“未支付订单到期自动关闭”这几部分中，当前项目里我帮你补充/修改过的关键代码位置。

## 1. 负责秒杀链路优化

### 1.1 核心业务代码

- `src/main/java/com/hmdp/service/impl/VoucherOrderServiceImpl.java`
    
    - `seckillVoucher(Long voucherId)`：`87-129`
        - 秒杀入口
        - 先校验秒杀券是否存在、活动是否开始/结束
        - 生成全局订单 ID
        - 调用 Lua 脚本做资格校验与 Redis 预扣
        - 资格通过后发送 Kafka 下单消息
        - 发送失败时执行 Redis 回滚
    - `sendSeckillOrderMessage(SeckillOrderMessage orderMessage)`：`131-150`
        - 发送 Kafka 秒杀消息
        - 异步发送失败时执行 Redis 回滚
    - `onSeckillOrderMessage(String payload)`：`152-159`
        - Kafka 消费入口
    - `handleSeckillOrderMessage(SeckillOrderMessage orderMessage)`：`161-187`
        - 按 `userId` 加 Redisson 锁
        - 防止同一用户消息并发消费
        - 构造订单对象并走事务代理创建订单
        - 消费失败时执行 Redis 回滚
    - `rollbackOrderQualification(Long voucherId, Long userId, Long orderId)`：`189-197`
        - 执行 Lua 回滚脚本
    - `createVoucherOrder(VoucherOrder voucherOrder)`：`203-230`
        - 数据库层再次校验一人一单
        - 通过 `stock > 0` 条件扣减库存
        - 扣减成功后创建订单
        - 订单默认状态设为未支付
- `src/main/resources/seckill.lua`
    
    - `1-18`
        - Redis 原子资格校验脚本
        - 判断库存是否充足
        - 判断用户是否已经抢购
        - 预扣 Redis 库存
        - 使用 `Hash(userId -> orderId)` 记录抢购资格
- `src/main/resources/seckill_rollback.lua`
    
    - `1-14`
        - Redis 回滚脚本
        - 只有当前 `userId` 对应的 `orderId` 一致时才回滚
        - 避免旧订单补偿误删新订单资格
- `src/main/java/com/hmdp/dto/SeckillOrderMessage.java`
    
    - `1-14`
        - Kafka 秒杀消息体
        - 包含 `orderId / userId / voucherId`

### 1.2 配置代码

    - `21-31`
        - Kafka 生产者/消费者基础配置
    - `38`
        - 秒杀订单 Topic：`hmdp.seckill.order`

    - `84-115`

    - `117-142`
        - 校验消费者会通过代理创建订单
    - `144-167`
        - 校验消费失败时会执行 Redis 回滚

### 1.4 这部分对应的简历表述

## 2. 负责缓存优化

### 2.1 核心业务代码

- `src/main/java/com/hmdp/service/impl/ShopServiceImpl.java`
    
    - `queryById(Long id)`：`45-59`
        - 店铺查询统一走 `CacheClient.queryWithLogicalExpire`
        - 对热点数据使用逻辑过期方案
- `src/main/java/com/hmdp/utils/CacheClient.java`
    
    - `set(String key, Object value, Long timeout, TimeUnit unit)`：`30-32`
        - 普通缓存写入
    - `setWithLogicalExpire(String key, Object value, Long timeout, TimeUnit unit)`：`34-39`
        - 逻辑过期缓存写入
    - `queryWithPassThrough(...)`：`41-65`
        - 缓存穿透解决方案
        - 查不到数据时缓存空值，设置空值 TTL
    - `queryWithLogicalExpire(...)`：`69-124`
        - 热点 Key 逻辑过期方案
        - 缓存过期后先返回旧值
        - 通过互斥锁异步重建缓存
    - `cacheNullValue(String key)`：`126-128`
        - 空值缓存写入
    - `tryLock / unlock`：`130-137`
        - 缓存重建互斥锁

### 2.2 这部分对应的核心点

- 热点 Key：逻辑过期，防止缓存击穿
- 空值缓存：防止缓存穿透
- 异步重建：提升热点数据访问稳定性

- `src/test/java/com/hmdp/utils/CacheClientTest.java`
    - 当前项目里已有对应测试，用于验证缓存工具类逻辑

## 4. 未支付订单到期自动关闭

### 4.1 调度入口

    - `9-12`

### 4.3 核心业务代码

    - `cancelOrderAndRestoreDbStock(Long orderId, Long voucherId)`：`232-252`
        - 把订单状态从未支付更新为已取消
        - 回补 MySQL 秒杀库存
        - 如果库存回补失败，则抛异常触发事务回滚
    - `closeExpiredUnpaidOrders(LocalDateTime expireBefore)`：`254-260`
        - 查询一批超时未支付订单并逐个处理
    - `listExpiredUnpaidOrders(LocalDateTime expireBefore)`：`262-268`
        - 查询待关单数据
    - `handleCloseOrderWithRetry(Long orderId, Long userId, Long voucherId, int retryCount)`：`270-283`

        - 失败则发送 Kafka 重试消息
    - `processCloseOrder(Long orderId, Long userId, Long voucherId)`：`285-308`
        - 校验订单是否存在、订单归属是否正确
        - 对未支付订单执行取消和回补库存
        - 成功后释放 Redis 抢购资格和 Redis 预扣库存
        - 如果订单已被取消，只释放 Redis 资格
    - `sendOrderCloseCompensationMessage(...)`：`310-316`
        - 发送关单补偿消息
    - `onOrderCloseCompensationMessage(String payload)`：`318-325`
