### String 为什么不可变？

String 不可变，主要有以下几个原因：

- `String` 类被 `final` 修饰，不能被继承，避免子类通过重写方法破坏其不可变性。
- String 内部用于存储字符的成员变量是 `private final` 的，说明这个引用一旦初始化后就不能再指向其他数组。
- String 没有提供修改内部字符内容的方法，像 `replace()`、`substring()`、`concat()` 这些操作，返回的都是一个新的 String 对象，而不是在原对象上修改。
- String 对内部数据做了封装，不会把可修改的内部存储直接暴露给外部，因此外部无法改动它的内容。

我给你逐条点评：

#### 1. “String类被final修饰”
- 这个是对的。

#### 2. “数组被final修饰，保证了引用地址不可变”
- 这句 **不严谨**。
- `final` 只能保证：
  - `value` 这个变量不能再指向别的数组
- 但不能保证：
  - 数组里面的元素不能改

也就是说，**final 修饰数组引用，不等于数组内容不可变**。

#### 3. “没有提供修改内部数组内容的方法”
- 这个基本是对的。
- 更准确地说，是：
  - 没有暴露修改内部存储内容的 API
  - 所有看起来“修改字符串”的操作，本质上都是创建新对象

### 更严谨一点的底层理解

早期 JDK 中，String 内部是：

```java
private final char[] value;
```

Java 9 以后，为了节省空间，改成了类似：

```java
private final byte[] value;
```

并配合 `coder` 来表示编码方式。  
但无论底层是 `char[]` 还是 `byte[]`，核心思想都一样：

- 内部存储引用不可变
- 内容不对外暴露
- 不提供原地修改能力
- 所有“修改”都产生新对象

---

### 顺便补一个常见追问：String 为什么要设计成不可变？

因为不可变带来很多好处：

- 可以安全地放进字符串常量池
- 可以缓存 `hashCode`，提高性能
- 天然线程安全
- 更适合作为 `HashMap` 的 key
- 更安全，像类加载、网络地址、文件路径等场景不容易被篡改
